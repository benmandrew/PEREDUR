# Config keys and provenance

What adding, moving or removing a config key does to archived campaigns, and how a binary and an archive record the commit they came from.

## Config keys

A new TOML key needs an entry in `k_config_keys` in `src/config/keys.hpp`, which drives the reader and the unknown-key warning in `src/config_io.cpp` and `config_json()` in `src/repair/manifest.cpp`. Its row also carries the key's schema description and its comment in the template, from which `src/config/reference.cpp` generates `schemas/config-schema.json` and `example-config.toml`: run `cmake --build build --target config-reference` after changing the table or a default, and the `config_reference` test fails until the checked-in files match. An enum-valued key also needs its spellings in `EnumNames` in `src/config/enum_names.hpp`, which both the parser and `run.json` use. A check that spans two keys is written by hand in `apply_toml`.

Both repair paths share one key set, and some keys are read by one path only: the `[mutation]` rewrite arms `p_trigger`, `p_response`, `p_timing`, `p_condition_type`, `p_scope` and `p_stop`, by FRETISH, and every `[tlsf.mutation]` key by TLSF. The `reader` column of `k_config_keys` marks them. A run warns on stderr about each key of the other path set to a non-default value, and its `run.json` records every such key as null. Neither is fatal, because campaign configs and `example-config.toml` set every key.

Every value in `example-config.toml` is its built-in default, written from `config_json(Config{})`, so copying the file whole is a no-op. The one exception is `runtime.parallel`, whose default is a call rather than a constant and so stays commented out. Eight keys had silently drifted in the hand-kept template before a check existed. `scripts/check_config_schema.py`, run by `lint`, holds `DEFAULTS` in `scripts/gen_configs.py` to the template's values; a key there is spelt as the template key it mirrors (no two template keys share a name, so the name alone finds it), or goes into `GEN_CONFIGS_EXEMPT` with its reason.

A knob is worth keeping only if some archived config sets it, so count the archived run configs that set one before adding it and when auditing. The per-filter run intervals, the `[syntactic]` weights, `tlsf.mutation.p_guarantee` and `runtime.report_cpu_timing` were removed after appearing in none of ~65k. The archives are no longer in this repository (see "Where the campaign records are" below) and their run configs were never tracked, so the count runs over the result trees the campaign hosts keep.

## Commit provenance

Every binary answers `--version` with `commit=`, `commit_short=` and `dirty=` lines, resolved at *build* time: `cmake/version.cmake` runs `cmake/write_version_header.cmake` on every build, which rewrites `build/generated/git_version.hpp` only when the commit changed. Configure-time resolution would report a stale HEAD after a new commit. Only `src/version.cpp` includes the header, and `dirty` counts modified *tracked* files only.

`scripts/run_experiments.py` reads `peredur --version` once at startup, never `git rev-parse`, and stamps `commit` and `dirty` onto every CSV row and a per-host manifest. It refuses to launch when a binary's commit differs from HEAD, was built dirty, or cannot be read, unless given `--allow-stale-binary`. Neither column may join the resume key in `run_experiments.py` or `KEY_FIELDS` in `merge_experiments.py`: archived rows have no commit, so every finished campaign would re-run.

Campaigns closed before this existed carry a reconstructed `PROVENANCE.json` (`"attribution": "inferred"`) whose `binary_commit` is `null` and must stay so; the "Commit attribution" section of `experiments/README.md` at `274d496` documents the method.

Each archive vendors the `gen_configs.py`, `run_experiments.py` and `merge_experiments.py` that ran it under `experiments/<campaign>/scripts/`, and `vendored_scripts` in `PROVENANCE.json` records each file's source commit and blob sha; check a copy with `git hash-object`. Attribution defaults to `profile_commit`, overridden where campaign content such as the `CSV_FIELDS` header pins the runner revision; `factorial`, `wellsep`, `genpop-sweeps` and `tlsf-genpop` are attributed that way, so do not "correct" them back. Recorded shas that are not ancestors of `main` are held reachable by annotated `provenance/*` tags, and no such tag may ever be deleted, because `git gc` would collect the objects. `provenance/tlsf-branch` holds `genpop-sweeps` and `tlsf-genpop`, which ran off the unmerged TLSF branch. `provenance/replicate-campaign` holds `2026-07-31-replicate`, whose branch was split into reconstructed pull requests. `provenance/assumption-reach` holds `2026-08-26-assumption-reach`, whose branch was rebased after the run; its shas are not repointed, since its results CSV stamps them. `provenance/selection-smoke` holds `2026-08-26-selection-smoke` and was cut *before* its branch was rebased, which is the order to keep, as a tag cut afterwards depends on `git reflog`. Re-check an archive whenever its branch is rebased, split or otherwise rewritten: blob shas survive a rewrite and commit shas do not, so the blob check cannot stand in for the tag. These paths, `README.md` and a campaign's pre-registered `PLAN.md` are the only tracked files under `experiments/`, via `.gitignore` negations that must re-open descent into any new subdirectory.

An archived config states only the keys its sweep overrides, so moving a C++ default silently changes what it means. Archived configs are not edited to compensate; record the move under "Config vintage" below. `allow_output_assumptions` and `run_well_separation` moved to `true` when `2026-08-06-wellsep-timing` closed and are now removed, so older archives reproduce only at their own commits. On 2026-09-11 `[mutation] p_condition_type` and `p_scope` moved from 0 to 0.15 and `p_monotone` to 0.25, so a FRETISH archive needs all three written in at `0.0`; the fitness weights moved from 0.2/0.5/0.5 to 0.1/0.2/0.7 that day, and `gen_configs.py` writes them into every config. `[mutation] p_stop` arrived on 2026-09-15 at 0.15; it draws only on a requirement with an `until` or `before` timing, and no archived specification has one, so it needs writing into no archived config.

*Removing* a key warns and ignores: `warn_unknown_keys` in `src/config_io.cpp` prints `config: unknown key <path>, ignoring`, with a `retired_key_hint` naming any replacement. Retire the sweeps and profiles that emit a key along with it. Those campaigns reproduce only at their own commits through their vendored `scripts/`, and `campaign.py collect --csv` still merges their archived CSVs. Removed so far:

- `[filters.intervals]`: TLSF sweep V and the `wellsep-timing` profile, whose campaign cannot be regenerated.
- `fitness.weight_halstead` (2026-08-13): sweep C.
- `[filters] run_weakening`, `run_well_separation`, and `[tlsf.mutation] p_monotone`, `connective_implies`, `monotone_atom_rules`, `monotone_extra_rules` (2026-09-11): FRETISH sweep J, TLSF sweeps W and Q, and the `cj-large`, `weakening-arbiter`, `wellsep`, `arbiter-hp` and `arbiter-padd` profiles. 79,236 of 79,255 archived configs set `run_weakening` and 12,323 set `run_well_separation`; the `monooff` arm of `2026-08-23-monotone` now runs at the 0.25 default.
- `[tlsf.mutation] p_burst_continue`, `p_remove_assumption`, `[mutation] allow_output_assumptions`, `[runtime] max_concurrent_realizability`, `ganak_timeout_ms` and `[filters] run_vacuity` (2026-09-11): archived configs set only `allow_output_assumptions` (12,323) and `max_concurrent_realizability` (4, in `2026-08-03-libspot-soak`).
- `[tlsf.mutation] max_assumption_width`, `p_bare_assumption` (2026-10-30): sweep U of `2026-08-26-assumption-reach`, whose profile had already retired.
- `[tlsf] repair_mode`, `muc_max_iterations` (2026-10-30): the `muc` profile of `2026-07-21` and sweep P of `2026-07-22`, both crossing the two modes.
- `[fitness] keyword_similarity`, `semantic_trace_weight` (2026-10-30): `gen_configs.py --pin-vintage` wrote both from 2026-10-06; no FRETISH campaign before that date states either.
- `[genetic] accumulate_repairs` (2026-10-30): the two arms of `2026-08-19-accumulator` and the sweeps that wrote it explicitly.
- `[model_counting] metric` (2026-10-30): every config `gen_configs.py` wrote, `direct` until 2026-10-30 and `logarithmic` since.

Retiring a key's *value* goes further, because the parser refuses it. On 2026-08-06 `nsga2` became `nsga2-truncate` and `nsga2-replicate` became `nsga2-apportion`, and the old spellings are rejected by name rather than aliased, so an archived config reproduces only at the commit its `PROVENANCE.json` names. `fitness.status_grading = "tiered"` and `genetic.selection_scheme = "nsga2-truncate"` went the same way on 2026-10-30, with no replacement spelling: each error names the surviving values.

Archived *results* still join. `scheme_of()` in `run_experiments.py` reads the scheme's directory name into the `selection` column of `KEY_FIELDS`, and `canonical_scheme()` in both scripts maps retired spellings onto new ones wherever `selection` is read back, so all 224,861 archived `nsga2` rows keep their resume key. Renaming any other factor directory needs a mapping entry too, or a finished campaign silently re-runs from zero.

## Run manifest schema versions

`k_schema_version` in `src/repair/manifest.cpp` is the `schema_version` field of `run.json`. It is bumped when a field is added, changes meaning or leaves, so a reader can tell which shape it is holding without guessing from which fields are present. Versions 17 to 19 have no record. Each version below names what changed from the one before.

- **2** added `fitness_cache`, `n_constant_folded` and `n_tautology_substitutions`, when those counters stopped printing to stdout by default and this became their only unconditional record. Anything `print_diagnostics_report` shows has to appear here too, or turning the flag off loses it.
- **3** added `input_screen`, so a campaign can partition its runs on whether the input itself failed a correctness check rather than grepping the log for the warning.
- **4** added `n_weak_operator_unresolved`. It counts satisfiability queries abandoned rather than answered, so a run that reports repairs with a non-zero count screened less than a run reporting the same repairs with zero — which is not visible from any other field.
- **5** added `budget_screen`, so a zero-yield run can be told apart from one whose ltlsynt budget could not decide its own input specification.
- **6** added `fitness.status_grading`, since the status objective now has two scales and a manifest that does not name the one in use cannot be read.
- **7** dropped `fitness.weight_halstead` along with the objective it weighted, so the objective vector is one shorter and a reader keying on its position against an older manifest reads the wrong component.
- **8** added `mutation.p_remove_guarantee`. The operator can delete a guarantee, so a repair may hold fewer requirements than the specification it came from, and a reader comparing counts needs to know whether the run could do that.
- **9** added `n_spot_decided` and `n_escalations_declined`, and redefined `tool_calls.black.calls` as black's own exec count rather than the satisfiability cache-miss count, which SPOT taking the first stage split in two. Comparing `black.calls` across the boundary compares different things.
- **10** added `n_well_separation_errors`. The well-separation query used to let an ltlsynt error end the run, so a run that finished implies zero of them; from this version a finished run may have dropped candidates on a non-answer, and only this field says how many.
- **11** added `input_screen_error`. Before it, a screen that raised ended the run before any manifest was written, so `input_screen: null` meant the input passed every check. From this version the run survives, and null means either that or a screen that never produced a verdict — this field is what tells them apart.
- **12** added `fitness.mrs_admission_order`. The MRS walk's score depends on the order it admits parts in, so two runs on one specification under one grading scale are not comparable without it.
- **13** added `genetic.accumulate_repairs` and `n_accumulated_repairs`. Before it a run's repairs all came from its final population, so the output was a function of the last generation alone; from this version the key can union in the repairs earlier generations found, and only this field says how many of them the run would otherwise have thrown away.
- **14** added `genetic.repaired_operators`. It selected between two mutation and crossover grammars with different RNG draw streams, so two runs of the same seed agreed only when they agreed on this key.
- **15** removed `genetic.repaired_operators`. The repaired grammar is now the only one, so the key no longer selects anything; a manifest at this version or later was written by a binary that has only that grammar.
- **16** added `n_ltlsynt_capability_errors`. Before it, an ltlsynt run that reported a limit of its own instead of a verdict ended the run and no manifest was written at all; from this version the query resolves as undecided and this field is the only record that it happened.
- **20** redefined `tool_calls.ltlfilt.calls` and added the caches block. `calls` counted `simplify_ltl`'s and `rewrite_weak_operators`' cache misses, while `total_s` beside it also covered every `spot_satisfiable` exec, which is memoised nowhere — so the field understated ltlfilt's true exec count by 35.5% over a 14-specification corpus and the seconds per call derived from the pair were over two different sets. It is now the exec count `total_s` is actually over. `caches` reports the hits and misses of every memo in the run, which no field carried before: the satisfiability cache's miss count reached no field at all (the black row reports black's own exec count, deliberately, since SPOT takes the first stage), and it is the largest cache in a run at 237,969 lookups over that corpus.
- **21** added `stopped_by`, `generations_run` and `individuals_bred`, with `genetic.termination`, `genetic.max_individuals` and `genetic.max_wall_s` beside them in the config block. A run could end only by exhausting `genetic.generations` before this version, so its wall time and its generation count said everything there was to say about how it stopped; from this version it can also spend an offspring budget or pass a deadline, and only `stopped_by` separates the three. `individuals_bred` is null wherever no budget was active, an unbudgeted run not paying for the count.
- **22** added `mutation.p_condition_type` and `mutation.p_scope`, the two directional arms over a requirement's scope and condition type.
- **23** added the implication block. The pairwise sweep's counters reached no field at all before it, so a run's diagnostics carried them and a campaign reading `run.json` could not: `n_equivalent_collapsed` in particular is the only record of how much of the output was one repair written twice, and it is unreadable without `n_comparisons` beside it to say how many pairs were asked.
- **24** added "aurus" to the values `fitness.status_grading` can take. It exists to be ablated against rather than to be run: it reproduces AuRUS's own ladder so a campaign can cross PEREDUR's grading against the design PEREDUR derives from, and it is the one scale that does not cap a candidate gaming its own assumptions. A reader keying on that field against an older manifest can assume it names one of two scales that do; from this version it may name a third that does not, so the status objective of two runs is comparable only where the field agrees.
- **25** added `mutation.p_monotone`, the FRETISH monotone rewrite arm. Its TLSF twin `tlsf.mutation.p_monotone` has been in the config block since the block existed, so a reader keying on the name alone now finds two.
- **26** added `implication.fingerprint_refuted`, the ordered pairs a sampled word settled ahead of the solver. It is the only reading of whether the prefilter worked on a given run, the pairs it refutes never reaching `comparisons`. The same version is where the FRETISH implication check stopped decomposing per requirement, so `comparisons`, `timeouts` and the repair counts beside them are not comparable across it on that path.
- **27** removed `tlsf.mutation.p_monotone` (folded into `mutation.p_monotone`, which both paths now read), `tlsf.mutation.connective_implies` and the two `tlsf.mutation.monotone_*_rules` gates (all now unconditional), and `filters.run_weakening` and `filters.run_well_separation` (the stages are gone). It also removed `filters.run_vacuity` (vacuity always runs per generation), `mutation.allow_output_assumptions` (always allowed), `tlsf.mutation.p_remove_assumption` and `p_burst_continue` (their operators are gone), `runtime.ganak_timeout_ms` (ganak runs untimed) and `runtime.max_concurrent_realizability` (no ltlsynt concurrency cap), and dropped `tool_calls.ganak.timeouts` with the timeout it counted. The same version moved the fitness weights to AuRUS's 0.1/0.2/0.7 and `mutation.p_condition_type`, `p_scope` and `p_monotone` off 0.
- **28** moved both paths onto one implication sweep and runs it during the search. On TLSF, `comparisons`, `skipped` and `duplicates` read 0 on every earlier manifest, the TLSF sweep having counted none of them, and `fingerprint_refuted` was never reset; all four now carry the sweep's own figures, as they already did on FRETISH. `timeouts` still reads 0 there, `tlsf_spec_implies` counting none. Wherever the run accumulates, the implication figures are the streamed sweep's, whose batches ask the pairs within a batch and between it and the maximal set so far, so `comparisons` and `skipped` do not compare with any earlier run's; `duplicates` reads 0, the stream deduplicating before its sweep sees anything. No key selects between the two routes, so a manifest at 28 or above carries the streamed figures whenever `accumulate_repairs` and `filters.run_implication` are both on.
- **29** added `mutation.p_stop`, the FRETISH arm rewriting the stop condition of an `until` or `before` timing. It draws nothing on a specification without one, so an earlier run's search is what it would have been at any value.
- **30** counts `implication.timeouts` on TLSF, where `tlsf_spec_implies` counted none and the field read 0 on every earlier TLSF manifest.
- **31** records the config keys a path never reads as null on that path: the FRETISH-only [mutation] rewrite arms on a TLSF run, and [tlsf] `muc_max_iterations` and [`tlsf.mutation`] on a FRETISH run. An earlier manifest records whatever the config said, which the search ignored.
- **32** added `fitness.keyword_similarity` and `fitness.semantic_trace_weight`, which place the FRETISH timing, scope and condition-type measures in the syntactic or the semantic objective. The default reproduces every earlier run, so an older manifest reads as `keyword_similarity` = "syntactic". Both are FRETISH-only and read null on a TLSF run.
- **33** added `mrs_screen`: how often the MRS walk's whole-specification satisfiability screen ran, fired and was left undecided. Zero under any other status grading, and absent before the screen existed.
- **34** added `n_model_probe_sat`: implication queries black answered SAT between SPOT's first look and its full budget. `tool_calls.black.calls` now counts those probes too, so an implication-heavy run reads far more black calls than one at 33, and `n_escalations_declined` still counts only the queries left undecided.
- **35** added `implication.residual_queries` and `implication.residual_settled`: the implication checks that dropped shared guarantees from the negated side, and those settled true with nothing left to ask.
- **36** added `implication.rule_covered`: the requirements a structural rule proved implied while building that shortened destination.
- **37** added `caches.realizability.rule_subsumed`: the realizability queries settled from a decided one by ordering the requirements they replaced.
- **38** added `caches.realizability.satisfiability_routed`: the realizability queries over no environment inputs decided by satisfiability rather than by ltlsynt. `tool_calls.ltlsynt.calls` no longer counts them, so a run on such a specification reads far fewer ltlsynt calls than one at 37.
- **39** added `implication.model_words` and `implication.model_refuted`: the solver models the prefilter adds to its sampled words, and the ordered pairs only a model word refuted. From this version `fingerprint_refuted` counts those pairs too, so it reads higher than at 38 wherever a model separated a pair.
- **40** added `caches.realizability.controller_reuse`: the realizability queries put to a stored controller, those it answered, and the guarantee checks that cost; and `tool_calls.controller_check`, the ltl2tgba and autfilt execs behind them. `tool_calls.ltlsynt.calls` falls by the hits.
- **41** added `runtime.mrs_speculation_depth` and `mrs_speculation`: the MRS walk's lookahead queries issued, started and later asked by the walk itself. The lookahead moves no score, but its untaken branches add ltlsynt execs, so `tool_calls.ltlsynt.calls` reads higher than at 40 at the default depth.
- **42** removed `caches.simplify_ltl` with the `simplify_ltl` pass, which no engine path had called for many versions; its row read zero hits and misses. `tool_calls.ltlfilt.cache_hits`, which counted that pass's hits and so read zero too, now counts the `remove_wm` memo's hits.
- **43** removed `tlsf.mutation.max_assumption_width` and `p_bare_assumption`, retired at their no-op defaults.
- **44** removed `tlsf.repair_mode` and `tlsf.muc_max_iterations` with the MUC-guided repair mode; every TLSF run is monolithic.
- **45** removed `fitness.keyword_similarity` and `fitness.semantic_trace_weight`; the FRETISH keyword orders always join the semantic objective at weight 1/2.
- **46** removed `genetic.accumulate_repairs`; every run accumulates.
- **47** removed `model_counting.metric`; trace counts always combine as logarithms.

## Where the campaign records are

The campaign archives under `experiments/` and the narrative log `EXPERIMENTS.md` left this repository after `274d496`, which is the last commit of `main` that holds them. A path of the form `experiments/<campaign>/...` or a reference to `EXPERIMENTS.md` in a comment or in these docs resolves at that commit: `git show 274d496:experiments/<campaign>/REPORT.md`. A campaign closed on its own branch after that commit resolves at its `provenance/<campaign>` tag. The campaigns behind the paper's evaluation are also in the paper's Zenodo artifact, with their raw output. Campaign tooling is unchanged, and a new campaign still writes to `experiments/`.

## Config vintage

`gen_configs.py` writes a key only when a sweep overrides it, so an archived config states a fraction of the settings its campaign ran under and inherits the rest from the binary. A moved C++ default therefore silently changes what an archived config means, and archived configs are not edited to compensate. An affected campaign reproduces at the commit its `PROVENANCE.json` names, through the vendored `scripts/` beside it. Where a value written into the config restores the old behaviour, the row names that value. A probability read before the `RandomSource` is drawn costs no draw at 0, so writing such a key in at `0.0` reproduces the breeding stream byte for byte; rows mark this *exact at 0*.
