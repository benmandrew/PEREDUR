# Config keys and provenance

What adding, moving or removing a config key does to archived campaigns, and how a binary and an archive record the commit they came from.

## Config keys

A new TOML key needs four edits that the compiler does not tie together: its `apply_*` reader in `src/config_io.cpp`, `config_json()` in `src/repair/manifest.cpp` (else it never reaches `run.json`), `config_key_spec()` in `src/config_io.cpp` (else the parser warns "unknown key"), and `schemas/config-schema.json` (else editors reject it). `scripts/check_config_schema.py`, run by `lint`, checks the last three against each other and against `example-config.toml`.

Every value in `example-config.toml` must equal its default in `include/config.hpp`, so copying the file whole is a no-op. The same script enforces this through `DEFAULT_FIELDS`; a new key goes there or into `UNPINNED_KEYS` (the enums and `runtime.parallel`), or the check fails. Eight keys had silently drifted before it existed.

A knob is worth keeping only if some archived config sets it, so count the configs under `experiments/` that set one before adding it and when auditing. The per-filter run intervals, the `[syntactic]` weights, `tlsf.mutation.p_guarantee` and `runtime.report_cpu_timing` were removed after appearing in none of ~65k. `python scripts/campaign.py describe --all --json` answers the same question per archive, and the configs win where the two disagree.

## Commit provenance

Every binary answers `--version` with `commit=`, `commit_short=` and `dirty=` lines, resolved at *build* time: `cmake/version.cmake` runs `cmake/write_version_header.cmake` on every build, which rewrites `build/generated/git_version.hpp` only when the commit changed. Configure-time resolution would report a stale HEAD after a new commit. Only `src/version.cpp` includes the header, and `dirty` counts modified *tracked* files only.

`scripts/run_experiments.py` reads `peredur --version` once at startup, never `git rev-parse`, and stamps `commit` and `dirty` onto every CSV row and a per-host manifest. It refuses to launch when a binary's commit differs from HEAD, was built dirty, or cannot be read, unless given `--allow-stale-binary`. Neither column may join the resume key in `run_experiments.py` or `KEY_FIELDS` in `merge_experiments.py`: archived rows have no commit, so every finished campaign would re-run.

Campaigns closed before this existed carry a reconstructed `PROVENANCE.json` (`"attribution": "inferred"`) whose `binary_commit` is `null` and must stay so; `experiments/README.md` documents the method.

Each archive vendors the `gen_configs.py`, `run_experiments.py` and `merge_experiments.py` that ran it under `experiments/<campaign>/scripts/`, and `vendored_scripts` in `PROVENANCE.json` records each file's source commit and blob sha; check a copy with `git hash-object`. Attribution defaults to `profile_commit`, overridden where campaign content such as the `CSV_FIELDS` header pins the runner revision; `factorial`, `wellsep`, `genpop-sweeps` and `tlsf-genpop` are attributed that way, so do not "correct" them back. Recorded shas that are not ancestors of `main` are held reachable by annotated `provenance/*` tags, and no such tag may ever be deleted, because `git gc` would collect the objects. `provenance/tlsf-branch` holds `genpop-sweeps` and `tlsf-genpop`, which ran off the unmerged TLSF branch. `provenance/replicate-campaign` holds `2026-07-31-replicate`, whose branch was split into reconstructed pull requests. `provenance/assumption-reach` holds `2026-08-26-assumption-reach`, whose branch was rebased after the run; its shas are not repointed, since its results CSV stamps them. `provenance/selection-smoke` holds `2026-08-26-selection-smoke` and was cut *before* its branch was rebased, which is the order to keep, as a tag cut afterwards depends on `git reflog`. Re-check an archive whenever its branch is rebased, split or otherwise rewritten: blob shas survive a rewrite and commit shas do not, so the blob check cannot stand in for the tag. These paths, `README.md` and a campaign's pre-registered `PLAN.md` are the only tracked files under `experiments/`, via `.gitignore` negations that must re-open descent into any new subdirectory.

An archived config states only the keys its sweep overrides, so moving a C++ default silently changes what it means. Archived configs are not edited to compensate; record the move in the "Config vintage" note in `experiments/README.md`. `allow_output_assumptions` and `run_well_separation` moved to `true` when `2026-08-06-wellsep-timing` closed and are now removed, so older archives reproduce only at their own commits. On 2026-09-11 `[mutation] p_condition_type` and `p_scope` moved from 0 to 0.15 and `p_monotone` to 0.25, so a FRETISH archive needs all three written in at `0.0`; the fitness weights moved from 0.2/0.5/0.5 to 0.1/0.2/0.7 that day, and `gen_configs.py` writes them into every config.

*Removing* a key warns and ignores: `warn_unknown_keys` in `src/config_io.cpp` prints `config: unknown key <path>, ignoring`, with a `retired_key_hint` naming any replacement. Retire the sweeps and profiles that emit a key along with it, keeping their `merge_experiments.py` entries; those campaigns reproduce only at their own commits through their vendored `scripts/`. Removed so far:

- `[filters.intervals]`: TLSF sweep V and the `wellsep-timing` profile, whose campaign cannot be regenerated.
- `fitness.weight_halstead` (2026-08-13): sweep C.
- `[filters] run_weakening`, `run_well_separation`, and `[tlsf.mutation] p_monotone`, `connective_implies`, `monotone_atom_rules`, `monotone_extra_rules` (2026-09-11): FRETISH sweep J, TLSF sweeps W and Q, and the `cj-large`, `weakening-arbiter`, `wellsep`, `arbiter-hp` and `arbiter-padd` profiles. 79,236 of 79,255 archived configs set `run_weakening` and 12,323 set `run_well_separation`; the `monooff` arm of `2026-08-23-monotone` now runs at the 0.25 default.
- `[tlsf.mutation] p_burst_continue`, `p_remove_assumption`, `[mutation] allow_output_assumptions`, `[runtime] max_concurrent_realizability`, `ganak_timeout_ms` and `[filters] run_vacuity` (2026-09-11): archived configs set only `allow_output_assumptions` (12,323) and `max_concurrent_realizability` (4, in `2026-08-03-libspot-soak`).

Retiring a key's *value* goes further, because the parser refuses it. On 2026-08-06 `nsga2` became `nsga2-truncate` and `nsga2-replicate` became `nsga2-apportion`, and the old spellings are rejected by name rather than aliased, so an archived config reproduces only at the commit its `PROVENANCE.json` names.

Archived *results* still join. `scheme_of()` in `run_experiments.py` reads the scheme's directory name into the `selection` column of `KEY_FIELDS`, and `canonical_scheme()` in both scripts maps retired spellings onto new ones wherever `selection` is read back, so all 224,861 archived `nsga2` rows keep their resume key. Renaming any other factor directory needs a mapping entry too, or a finished campaign silently re-runs from zero.
