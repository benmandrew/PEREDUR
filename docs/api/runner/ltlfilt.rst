runner/ltlfilt.hpp
==================

Wraps SPOT's ``ltlfilt`` for the four passes this codebase drives: ``--simplify`` (``simplify_ltl``), ``--remove-wm`` (``rewrite_weak_operators``), ``--satisfiable`` (``spot_satisfiable``) and ``--equivalent-to`` (``ltl_equivalent``). The first two memoise on the canonical key, so the subprocess runs at most once per formula rather than once per spelling of one. On binary inaccessibility, a non-zero exit or a timeout, ``simplify_ltl`` returns its input unchanged and ``rewrite_weak_operators`` returns nothing at all, its caller needing the rewrite to have actually happened. ``spot_satisfiable`` is deliberately unmemoised, its caller caching the decided verdict a layer up. ``LtlfiltStats`` counts each entry point's execs separately, since reporting one pass's count against the wall time of all of them understated the true figure by 35.5%.

No engine path calls ``simplify_ltl`` any more: ``SatisfiabilityChecker::check_satisfiability`` was the last, and dropped it because the pass cost 8x the ``--satisfiable`` call it preceded. The other tool wrappers had already moved to a ``formula_key`` key: the pass blows up super-exponentially on the deep nested-X conjunctions ``run_ltl2tgba_for_counting`` and ``RealizabilityChecker::check_realizability`` ask about, and it eliminates a variable wherever one term subsumes another, which ``run_ganak_on_formula`` cannot afford because its caller multiplies the count over the wider alphabet. A ``normalize_ltl`` wrapper, which hid a constant result behind the original formula, was removed once that last move left it with no caller.
